```text
JSON Explorer 1.1.0: explore, query, compare, validate, repair, format and convert JSON.
Everything runs locally: nothing is uploaded, and no command uses the network.

Usage: json-explorer <command> [options]      (files: JSON, JSONC or JSON Lines; "-" reads stdin)

Commands:
  explore    Write an interactive graph/tree viewer as one offline HTML file (no network)
  outline    Summarize structure: fields, types, presence, formats, ranges (no raw values by default)
  query      Extract values with JSONPath (RFC 9535) or JSON Pointer, exactly as written
  diff       Structural differences by path, ignoring key order and formatting (exit 1 if any)
  validate   Check syntax (friendly errors with line/column) and optionally a JSON Schema
  repair     Fix common mistakes: quotes, commas, comments, Python literals, truncation…
  format     Pretty-print losslessly (numbers, escapes and key order untouched)
  minify     Remove all insignificant whitespace, losslessly
  sort-keys  Sort object keys recursively (code point order, like jq -S), losslessly
  convert    Convert to TypeScript types, JSON Schema, YAML, CSV/TSV, JSON Lines or JSON

Run "json-explorer <command> --help" for its options and examples.
Exit status: 0 success · 1 check failed (invalid, different, would change) · 2 error.
```

## explore

```text
Usage: json-explorer explore <file> [-o <viewer.html>] [--view graph|tree] [--title <text>]

Creates a self-contained page with an interactive graph and tree of the document: search,
expand/collapse, details with exact values and paths, a table view for lists of records,
conversions and image export. The data stays inside the file; a strict Content Security
Policy blocks every network request. The page is readable only by you and, by default, goes to
a private folder in your user cache (outside the project, so it is never committed with it;
set JSON_EXPLORER_PAGES to use another folder). Pages there are deleted after a week.

Options:
  -o, --out <value>   Where to write the page instead of the private pages folder.
  --view <value>      Start in the graph (default) or tree view.
  --title <value>     Page title (default: the file name).
  --force             Allow documents over 200 MB (browsers may struggle).
  --jsonl             Read the input as JSON Lines (one JSON value per line).
  --jsonc             Allow comments and trailing commas (JSONC).
  --strict            Read the input as strict JSON even if its name suggests JSONC.
  --max-size <value>  Largest file to load whole, in MB (default 200).

Examples:
  json-explorer explore data.json
  json-explorer explore events.jsonl --view tree
  json-explorer explore response.json -o response.html
```

## outline

```text
Usage: json-explorer outline <file> [--path <jsonpath>] [--depth <n>] [--samples <n>] [--top <n>] [--json]

Maps a document without printing its data: every path (array items folded into [*]), its
types, how often it is present, string formats and lengths, number ranges and distinct counts.
JSON Lines files are streamed, so any size works. Fields whose names suggest secrets never
show samples or common values.

Options:
  --path <value>       Outline only what this JSONPath (or JSON Pointer) selects. For JSON Lines, $ is the list of records, as in query.
  --depth <value>      Show paths up to this nesting depth.
  --samples <value>    Include up to N example values per path (default 0: none).
  --top <value>        Include the N most common values of each field, with how often each occurs (default 0: none).
  --max-paths <value>  Show at most this many paths (default 200).
  --records <value>    JSON Lines: analyze only the first N records.
  --json               Print the outline as JSON.
  --jsonl              Read the input as JSON Lines (one JSON value per line).
  --jsonc              Allow comments and trailing commas (JSONC).
  --strict             Read the input as strict JSON even if its name suggests JSONC.
  --max-size <value>   Largest file to load whole, in MB (default 200).

Examples:
  json-explorer outline data.json
  json-explorer outline events.jsonl --samples 3
  json-explorer outline events.jsonl --path '$[*].level' --top 5
  json-explorer outline api.json --path '$.data.items[*]' --depth 3
```

## query

```text
Usage: json-explorer query <file> <path>... [--limit <n>] [--count] [--paths] [--values] [--raw] [--json] [--exit-status] [-o <file>]

Prints each match as "path: value". Paths are JSONPath (RFC 9535): $.a.b, $.items[0], $.items[-1],
$.items[0:5], $.items[*].name, $..email, $.items[?@.price > 10], $[?@.level == 'error'],
$[?match(@.id, 'a.*')], length(), count(), value(), search(); or JSON Pointers like /items/0/name.
Numbers keep every digit. Secret-looking values are masked, and filters read them as absent, unless --show-secrets.
For JSON Lines, $ is the list of records; queries that pick records one by one ($[*]…, $[?…]…)
are streamed, so they work on files of any size.

Options:
  --limit <value>      Show at most N matches per path (default 50; 0 = all).
  --count              Print only the number of matches.
  --paths              Print only the paths of the matches.
  --values             Print only the values (add --compact for one line per match).
  --raw                Print strings without quotes (implies --values).
  --compact            Print each value on one line.
  --max-chars <value>  Truncate each printed value after N characters (default 4000; 0 = never).
  --json               Print the matches as JSON: [{ "query", "total", "matches": [{ "path", "value" }] }] (with --count only the totals, with --paths no values).
  -o, --out <value>    Write the matched value (or an array of matches) to a file instead.
  --exit-status        Exit with 1 when a query matches nothing, as grep does (by default the exit status is 0 either way).
  --show-secrets       Show values that look like secrets instead of [REDACTED].
  --jsonl              Read the input as JSON Lines (one JSON value per line).
  --jsonc              Allow comments and trailing commas (JSONC).
  --strict             Read the input as strict JSON even if its name suggests JSONC.
  --max-size <value>   Largest file to load whole, in MB (default 200).

Examples:
  json-explorer query data.json '$.users[0]'
  json-explorer query data.json '$..email' --count
  json-explorer query events.jsonl '$[?@.level == "error"].message' --values
  json-explorer query config.json /server/port
```

## diff

```text
Usage: json-explorer diff <before> <after> [--ignore <jsonpath>]... [--limit <n>] [--html <report.html>] [--json]

Compares values, not text: key order and whitespace are ignored, numbers compare by exact value
(1.5 equals 1.50; two 64-bit ids that differ are different). Arrays are aligned so an inserted
item is one change. Records are matched by their id (id, _id, uuid, guid, sku, or a key such as
productId or order_id), else by key or name; an item found at another position is reported as
moved, or if it also changed, by its changes (with where it was). Two records with different
ids are never paired.
Exit status: 0 when the data is the same, 1 when it differs, 2 on errors.

Options:
  --ignore <value>       Ignore everything at and under these JSONPaths (repeatable), e.g. timestamps.
  --limit <value>        List at most N differences (default 100; 0 = all).
  --array-match <value>  "align" (default: find inserted, removed and moved items), "unordered" (the same, but moving an item is not a difference) or "index" (compare position by position).
  --html <value>         Also write a visual report (offline HTML page, same --ignore and --array-match) to this file, or with "-" to the private pages folder (see explore).
  --json                 Print the differences as JSON.
  --show-secrets         Show values that look like secrets instead of [REDACTED].
  --jsonl                Read the input as JSON Lines (one JSON value per line).
  --jsonc                Allow comments and trailing commas (JSONC).
  --strict               Read the input as strict JSON even if its name suggests JSONC.
  --max-size <value>     Largest file to load whole, in MB (default 200).

Examples:
  json-explorer diff old.json new.json
  json-explorer diff a.json b.json --ignore '$..updatedAt' --ignore '$.meta'
  json-explorer diff before.json after.json --array-match unordered
  json-explorer diff expected.json actual.json --html -
```

## validate

```text
Usage: json-explorer validate <file>... [--schema <schema.json>] [--max-errors <n>] [--json]

Reports the first syntax error of each file with a code excerpt and a plain explanation, and
warns about duplicate keys and numbers that lose precision in JavaScript. With --schema, also
validates the data against a JSON Schema (draft-06, draft-07, 2019-09 or 2020-12).
JSON Lines files are checked line by line and streamed, so any size works.
Exit status: 0 when everything is valid, 1 when something is not, 2 on errors (such as a file
that cannot be read).

Options:
  --schema <value>      Also validate against this JSON Schema file.
  --max-errors <value>  Report at most N errors or warnings per file (default 20).
  --json                Print the results as JSON.
  --show-secrets        Show values that look like secrets instead of [REDACTED].
  --jsonl               Read the input as JSON Lines (one JSON value per line).
  --jsonc               Allow comments and trailing commas (JSONC).
  --strict              Read the input as strict JSON even if its name suggests JSONC.
  --max-size <value>    Largest file to load whole, in MB (default 200).

Examples:
  json-explorer validate config.json
  json-explorer validate data/*.json
  json-explorer validate events.jsonl
  json-explorer validate response.json --schema response.schema.json
```

## repair

```text
Usage: json-explorer repair <file> [-o <out> | -i] [--diff] [--indent 2|4|tab]

Turns almost-JSON into valid JSON: single quotes, unquoted keys, trailing or missing commas,
comments, Python None/True/False, NaN, JSONP wrappers, unclosed brackets, and more. Values are
kept as written. Prints the repaired JSON (or writes it with -o / -i); --diff shows what changed.
JSON Lines files are repaired line by line.

Options:
  -o, --out <value>   Write the repaired JSON to this file.
  -i, --in-place      Fix the file itself (written atomically).
  --diff              Show what was changed (instead of printing the JSON, unless -o/-i). Secrets are masked.
  --indent <value>    Also pretty-print the result: 2, 4, tab or 0 (minified).
  --show-secrets      Show values that look like secrets instead of [REDACTED].
  --jsonl             Read the input as JSON Lines (one JSON value per line).
  --jsonc             Allow comments and trailing commas (JSONC).
  --strict            Read the input as strict JSON even if its name suggests JSONC.
  --max-size <value>  Largest file to load whole, in MB (default 200).

Examples:
  json-explorer repair broken.json --diff
  json-explorer repair broken.json -i
  json-explorer repair - < broken.txt > fixed.json
```

## format

```text
Usage: json-explorer format <file>... [-o <out> | -i | --check] [--indent 2|4|tab]

Re-indents JSON without re-serializing it: literals such as 1.50 or 12345678901234567890 stay
exactly as written. JSONC files keep their comments. Use --check in CI to verify formatting.

Options:
  --indent <value>    Indentation: a number of spaces (default 2) or "tab".
  -o, --out <value>   Write the result to this file.
  -i, --in-place      Rewrite the files themselves (atomically).
  --check             Change nothing; exit 1 if any file would change (for CI).
  --final-newline     End with a newline (default; --no-final-newline to omit).
  --jsonl             Read the input as JSON Lines (one JSON value per line).
  --jsonc             Allow comments and trailing commas (JSONC).
  --strict            Read the input as strict JSON even if its name suggests JSONC.
  --max-size <value>  Largest file to load whole, in MB (default 200).

Examples:
  json-explorer format data.json -i
  json-explorer format *.json --check
  json-explorer format min.json --indent 4 -o pretty.json
```

## convert

```text
Usage: json-explorer convert <file> --to <ts|schema|yaml|csv|tsv|jsonl|json> [--path <jsonpath>] [--name <Name>] [-o <out>]

ts / schema infer types from every record (fields missing from some records become optional).
yaml writes YAML that parses back to the same data (YAML 1.1 and 1.2). csv / tsv flatten nested
objects into columns (owner.name) and neutralise spreadsheet formulas. jsonl writes one record per
line; json writes pretty JSON (e.g. from JSON Lines or JSONC). Numbers keep every digit.
For JSON Lines input, ts and schema describe one record.

Options:
  --to <value>         Output format: ts, schema, yaml, csv, tsv, jsonl or json.
  --path <value>       Convert only what this JSONPath selects (several matches become a list).
  --name <value>       Root type name (ts) or title (schema).
  --delimiter <value>  CSV field delimiter (default ",").
  -o, --out <value>    Write the result to this file.
  --show-secrets       Let --path filters read values that look like secrets (by default they read them as absent).
  --jsonl              Read the input as JSON Lines (one JSON value per line).
  --jsonc              Allow comments and trailing commas (JSONC).
  --strict             Read the input as strict JSON even if its name suggests JSONC.
  --max-size <value>   Largest file to load whole, in MB (default 200).

Examples:
  json-explorer convert response.json --to ts --name ApiResponse
  json-explorer convert users.json --to csv -o users.csv
  json-explorer convert api.json --path '$.data.items[*]' --to schema
  json-explorer convert events.jsonl --to csv
```
